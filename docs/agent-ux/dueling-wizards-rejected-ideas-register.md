# Dueling-Wizards Rejected Ideas Register

This document is the human-facing companion for
`tests/fixtures/contracts/dueling_wizards_rejected_ideas_register.json`,
enforced by
`tests/contracts/dueling_wizards_rejected_ideas_register.rs`.

`bd-1n0np.14` is a decision record, not an implementation queue. It records
ideas generated by the dueling-wizards process that were scored, challenged,
and rejected so future planning does not spend another round rediscovering the
same failure modes.

## Reopen Rule

Do not reopen a killed idea as product work without new evidence that changes
the original rationale. New evidence means a measured workflow result,
regression, benchmark, or corpus finding, not a better-sounding restatement of
the same proposal.

If a rejected mechanism is revisited, it must come back as an explicit lab,
evaluation, or curation candidate first. It must not silently mutate live packs,
trust scores, memory maturity, or retrieval policy.

## Reopen Evidence Matrix

The fixture carries `reopenEvidenceMatrix` rows for every killed idea. A row
may reopen only after at least one concrete evidence item of an accepted kind:

| Accepted kind | Meaning |
| --- | --- |
| `measured_workflow_result` | A real agent workflow result changes the original critique. |
| `regression` | A current regression shows the rejected mechanism solves a real failure. |
| `benchmark` | A controlled benchmark proves the mechanism without harming determinism. |
| `corpus_finding` | Corpus evidence shows the original rationale no longer holds. |

The matrix explicitly rejects `restated_proposal`, `aesthetic_preference`, and
`unmeasured_opinion` as reopen evidence. Every killed idea must remain
`forbidden_until_deterministic_proof` for live policy mutation and
`br_only_when_tracker_authoritative` for Beads mutation.

## Guardrails

The register pins these rules:

- `reopen_requires_new_evidence`: a future duel may revisit an idea only after
  concrete evidence changes the original critique.
- `lab_mode_before_live_policy`: experimental mechanisms must start in explicit
  lab or eval mode before affecting live agent packs.
- `candidate_not_auto_mutation`: drift, decay, demotion, or trust changes must
  create curation candidates rather than silently mutating memory state.
- `determinism_preserved`: proposals that change pack contents or pack hashes
  must carry pinned inputs, versioned transforms, and deterministic output
  contracts before they can ship.

## Maintenance

When a future duel kills or reframes another idea, append it to
`tests/fixtures/contracts/dueling_wizards_rejected_ideas_register.json`, update
this document, and preserve the score, source, rationale, and reopen policy.
The contract test should fail if a killed idea loses its score, source, or
`requires_new_evidence` policy.

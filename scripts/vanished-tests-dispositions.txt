# Dispositions for `#[test]` functions that a commit deleted and nothing
# restored, as surfaced by scripts/audit-vanished-tests.py (bd-z1dus, bd-0rkti).
#
# WHY THIS FILE EXISTS. The detector worked; its FINDINGS EXPIRED. `--since`
# defaulted to a rolling `60 days ago`, nothing recorded which findings had been
# triaged, and the tool exited 0 while printing them. So an untriaged deletion
# did not stay surfaced: it aged out, and the report got CLEANER while the tree
# did not. Measured 2026-10-25: a 2026-10-19 run with `--since 2026-09-05`
# reported 12 names and that day's default run reported 11 -- the windows are
# not nested, so the sets differed in BOTH directions -- and `05020689c` was two
# days from leaving the default window with six names dispositioned nowhere in
# the tracker.
#
# A detector whose output shrinks with the CLOCK rather than with REPAIR is not
# a ratchet. This file makes it one, in two ways that only work together:
#
#   1. The window's lower bound is the baseline COMMIT below, not a date, so it
#      can only grow as HEAD advances. A finding cannot expire.
#   2. Every surfaced name must appear here, so the gate exits NONZERO on an
#      untriaged one. An UNDISPOSITIONED name is the only thing that stands out.
#
# SHRINK-ONLY IN BOTH DIRECTIONS, the MESH_EMITTED_CODES_WITHOUT_FIXTURE idiom.
# An undispositioned name fails. So does a row whose name is no longer
# surfaced: with a growing window the only way that happens is that the test
# came back, which makes the row a statement about the past. Deleting a row is
# then the correct action, and it is the only correct direction.
#
# FORMAT  name<TAB>disposition<TAB>reason
#
#   retired   The assertion is deliberately gone. The thing it asserted is no
#             longer a property worth asserting, or asserting it tests
#             something other than this project's code.
#   replaced  Another test or gate asserts the same property, named in the
#             reason. This is the verdict a name-based sweep cannot reach on its
#             own -- it is why the tool prints what the removing commit ADDED.
#   owed      A real coverage loss, not yet restored. The reason must say what
#             is unasserted, precisely enough that restoring it is mechanical.
#
# A reason is MANDATORY for every row and the parser refuses a row without one.
# A disposition with no stated why would let someone clear this gate while
# recording nothing, which is the gate's own failure mode written into its input.
#
# WHY THE BASELINE IS HERE AND NOT EARLIER. 2026-10-25: `05020689c` is the
# oldest commit the 60-day window still surfaced, so its parent is the earliest
# bound that keeps exactly the set that was measured and triaged. Moving it
# EARLIER is how coverage grows later, and it will surface names nobody has
# triaged -- which is the point, and is work, not a regression.
#
# baseline-commit: ddbd1dea939053435a251c01e33092b0f1366eaa
